# Tidy comments

Code gets written with a comment above every block explaining what the block
plainly says. That noise survives into the PR and reviewers scroll past it. This
skill removes it, in any language, from the changed lines only.

## The test

A comment earns its place by doing one of two things:

1. **Naming the feature** the code enables — why it exists at all.
2. **Stating an invariant a future edit could silently break** — a required
   ordering, the reason a guard exists, a non-obvious external constraint, the
   regression a test specifically catches.

Everything else goes. The operative question for each comment: *if I delete
this, does a future reader lose anything?* If no, delete it.

## Cut these

| Pattern | Example |
|---|---|
| Restates the next line | `# create the resource group` above `resource "azurerm_resource_group"` |
| Narrates control flow | `# loop over each item` above a `for_each` / `.map()` |
| Restates an assertion | `// assert the result is 2` above `expect(x).toBe(2)` |
| Section banners with no content | `# ---- Variables ----`, `### CONFIG ###` |
| AI / dev-cycle narration | `# Added in this PR`, `# As requested`, `# Updated to fix the bug`, `# NEW:`, `# Changed from X to Y` |
| Changelog in the source | `# 2026-09-01: added retry` — that's what git log is for |
| Commented-out code | any dead block left "just in case" — git has it |
| Restates a self-evident name | `# The subscription ID` above `subscription_id` |
| Type restatement | `# returns a string` where the signature already says `-> str` |

## Never touch these

Deleting one of these breaks the build, the linter, or a compliance gate. When
in doubt, keep.

- **Linter / scanner directives**: `# noqa`, `# type: ignore`, `# nosec`,
  `# pylint: disable`, `//nolint:`, `# shellcheck disable=`, `# yamllint disable`,
  `# tflint-ignore:`, `# checkov:skip=`, `# trivy:ignore`, `eslint-disable`,
  `@ts-expect-error`, `@ts-ignore`, `# hadolint ignore=`
- **Compiler / tooling pragmas**: shebangs, `//go:build`, `# -*- coding: -*-`,
  `# language=`, `#pragma`, `# renovate:`, `# dependabot`, `# fmt: off`
- **Generated-block markers**: `<!-- BEGIN_TF_DOCS -->`, `# Code generated by
  ... DO NOT EDIT`, OpenAPI/codegen fences
- **License and SPDX headers**: `# SPDX-License-Identifier:`, copyright blocks
- **Comments that are the product**: a `description` field in Terraform or a
  JSON schema, OpenAPI `description:`, JSDoc on an exported public API, help
  text rendered to a user
- **`TODO` / `FIXME` with an owner or issue link** — keep. A bare `# TODO` with
  no referent is noise; cut it or ask.
- **Anything on a line you did not change.** Out of scope.

## Procedure

1. **Get the scope.** `git diff --stat` against the base branch (or the staged
   set if pushing a WIP). Only files with changes are in scope.
2. **Read the changed hunks**, not the whole file. A comment is in scope only if
   it sits on an added or modified line.
3. **Judge each comment** against the test above. Default to cutting — a comment
   that survives should be one you can justify in a sentence.
4. **Rewrite rather than delete** when a comment gestures at something real but
   buries it. `# this is important because of how the module works` becomes
   `# the role assignment needs principal_id to already exist` or it goes.
5. **Collapse re-narration.** If five comments in a file each re-explain part of
   the same design, that design belongs in the PR description or one line at the
   top of the file — not repeated per block.
6. **Apply the edits.** Do not produce a report and stop.
7. **Verify nothing else moved.** `git diff` should show comment-only deletions.
   If a code line changed, you went too far — revert that part.
8. **Report one line**: how many comments cut, across how many files, and name
   anything you deliberately kept that looked cuttable.

## Rewrite examples

```hcl
# Bad
# Create the storage account for the registry
# This uses the standard tier
resource "azurerm_storage_account" "registry" { ... }

# Good — the name and the args already say all of that
resource "azurerm_storage_account" "registry" { ... }
```

```yaml
# Bad
# Checkout the repository
- uses: actions/checkout@v4
# Set up node
- uses: actions/setup-node@v4

# Good — plus a comment that actually earns its line
- uses: actions/checkout@v4
  # full history required: the version bump reads tags
  with: { fetch-depth: 0 }
- uses: actions/setup-node@v4
```

```python
# Bad
# Retry the request 3 times
for attempt in range(3):

# Good
# the upstream API 502s on cold start; 3 attempts covers the observed worst case
for attempt in range(3):
```

## Scope discipline

This skill only removes comments. It does not rename things, restructure code,
fix bugs, or reformat. If the code itself is convoluted, say so in one line and
leave it — that is `/simplify` or `/code-review`, not this.
